# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

LaTeX source of Nusrat Begum's M.Sc. thesis, "Feature Drift Detection Techniques via Adversarial Validation" (Mahidol University, advisor Asst. Prof. Thanapon Noraset). Working branch: `concept-drift-adversarial-thesis` (not `main`). The advisor reads the thesis in Overleaf, which is a separate git remote and must be synced after each push.

Overleaf sync: the Overleaf project (git bridge, branch `main`) has its own history with no commits in common with GitHub. Each sync is one snapshot commit on top of Overleaf `main` whose tree is this repo's HEAD without `CLAUDE.md`, message "Sync with GitHub <sha>: <summary>". Before syncing, check that Overleaf's tree still equals the last synced GitHub commit (no edits made in Overleaf). The git token is supplied by the user; never write it into a remote, file or commit.

## Commands

```bash
export PATH=/Library/TeX/texbin:$PATH
pdflatex -interaction=nonstopmode main.tex && bibtex main && pdflatex -interaction=nonstopmode main.tex && pdflatex -interaction=nonstopmode main.tex
grep -c "Overfull\|undefined\|^!" main.log        # must be 0
pdflatex hypothesis_summary.tex                   # the two-page A4 summary, compiled separately
```

`latexmk` is not installed locally. `main.pdf` and `hypothesis_summary.pdf` are committed; rebuild both before committing text changes.

## Structure

- `main.tex` loads the class `muthesis2026.cls` (Mahidol template, FGS announcement PR07284) and inputs `preamble.tex` (names, committee, keywords), `abstract.tex`, `thesis.tex` (all six chapters in one file) and `appendix_impl.tex`. It also patches three template problems (lists of tables/figures, REFERENCES in the contents, `\inputrows`); keep those patches. Pseudocode uses `algorithm` + `algpseudocode`.
- `tables/*.tex` are table rows generated by `analyze_hypotheses.py` in the sibling repo `unsupervised-concept-drift-detection` (`experiments/results_hypotheses/latex/`). Never edit them by hand: regenerate and copy. `\inputrows{tables/x.tex}` inserts them; the same files feed Chapter 4 and `hypothesis_summary.tex`, which must stay in sync. Exception: Table `tab:tests` (`thesis.tex`, Section 4.5) is typed by hand from `tables/tests_rows.tex`, which is not inputted; check it by hand after regenerating.
- `figures/detection_*.pdf` and `threshold_sensitivity.pdf` come from `make_hypothesis_figures.py` in the code repo.
- Numbers quoted in prose are typed by hand. After regenerating tables, check every number in the abstract, Ch 1 contributions, Ch 4-6 and `hypothesis_summary.tex` against the tables.

## Writing rules (from the advisor)

- Never "novel"/"novelty"; no em-dashes; avoid "explainability"; modest claims ("we propose").
- Findings as short paragraphs tied to a hypothesis, never numbered lists.
- Cite terms on first use; use "classifier two-sample test (C2ST)".
- Literature review groups methods and compares them, not one paper per paragraph.
- Long captions need a short form: `\caption[Short]{Long}`.
- Keep the proposal title. Hypotheses H1-H3 stay as stated in the proposal; report outcomes honestly.
- International track: no Thai abstract or title needed.
