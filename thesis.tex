\chapter{Introduction} \label{chap:intro}

\section{Background and Significance}
Machine learning models deployed in production environments operate under the assumption that future data will resemble training data. This assumption is routinely violated: the statistical properties of input features, label distributions, or the conditional relationship between inputs and outputs evolve over time, a phenomenon collectively termed \textit{distribution drift} \citep{Lu2018, Gama2014}. Left undetected, drift degrades model performance silently, accumulating technical debt and operational risk \citep{Sculley2015, Bayram2022}. \citet{WidmerKubat1996} established that early detection of such changes is essential for maintaining reliable inference in non-stationary environments.

The practical consequences are well documented. \citet{Vela2022} demonstrated that clinical prediction models exhibit measurable accuracy degradation within months of deployment due to temporal distribution shift. \citet{NestorEtAl2019} corroborated this finding, showing that models for common clinical tasks failed to generalise across temporally shifted patient cohorts within the same hospital system. In such settings, an alarm that only states that drift occurred leaves practitioners to work out whether the cause is a specific feature pipeline, a population-level shift, or a data quality failure \citep{Sculley2015}.

The drift detection landscape has matured considerably. Statistical methods employ hypothesis tests such as the Kolmogorov--Smirnov test or Maximum Mean Discrepancy to compare reference and current distributions \citep{Rabanser2019, Gretton2012}. Adaptive windowing methods like ADWIN dynamically adjust historical baselines \citep{BifetGavalda2007}. Supervised error-based detectors (DDM, EDDM) monitor model error rates but require ground-truth labels \citep{Gama2004, BaenaGarcia2006}. Prediction-based methods track model outputs but depend on calibration quality \citep{Sethi2017, Guo2017}. Despite this diversity, several challenges remain. Univariate tests are run once per feature, so they raise more false alarms as the number of features grows; supervised methods cannot operate when labels are delayed or unavailable; and most detectors report only whether drift occurred, not which features changed \citep{Lu2018, Webb2016}.

The discriminative approach recasts distribution comparison as a classification problem. \citet{LopezPazOquab2017} formalised this as the \textit{classifier two-sample test} (C2ST): if an auxiliary classifier can reliably separate reference from current data based solely on features, the distributions differ. In machine learning practice the same procedure is called \textit{adversarial validation} \citep{Pan2020}. This thesis studies adversarial validation as a technique for feature drift detection and uses the term C2ST when it refers to the statistical test. \citet{Gozuacik2019} adapted this principle for streaming drift detection as the Discriminative Drift Detector (D3), which is one of the three detectors recommended by the benchmark of \citet{Lukats2024} and achieved the best mean time ratio in its experiments. D3 has three practical limitations. First, it signals drift when the AUC of a logistic regression classifier exceeds a fixed threshold of 0.7, and this threshold is not calibrated as a statistical test. Second, it compares two short adjacent windows, so a slow drift that changes both windows together can go unnoticed. Third, it discards the trained classifier after computing the AUC, so it gives no indication of which features drove the alarm.

Each of these limitations has been studied separately. Permutation tests can calibrate the C2ST statistic \citep{LopezPazOquab2017}, and sequential Monte Carlo methods reduce the number of permutations that such tests need \citep{Gandy2009}. SHAP \citep{Lundberg2017} has been applied to domain classifiers to rank drifted features \citep{Maggio2021} and to the explanations of deployed models to detect shifts that change model behaviour \citep{Mougan2025}. \citet{TRIPODD2024} test feature interactions for drift, but the interactions must be specified in advance and the cost grows quadratically with the number of features. \citet{HDPD2024} attribute performance changes to features but need ground-truth labels, and \citet{HinderFeature2024} define feature-wise drift formally without providing a streaming detector. This thesis combines a permutation test with sequential stopping, a long-memory reference window and a feature ranking in one unsupervised streaming detector, and compares it with D3 and other unsupervised detectors on real-world data streams.

\section{Research Objectives}
The thesis proposal set the goal of investigating adversarial validation as a feature drift detection technique. The objectives of this thesis are:

\begin{enumerate}
    \item To develop Enhanced Adversarial Drift Detection (EADD), an unsupervised feature drift detector that applies adversarial validation to data streams with a long-memory reference window and a permutation test that confirms each alarm.

    \item To compare EADD with D3 and other unsupervised drift detectors on real-world data streams in terms of recall, detection delay and false alarms.

    \item To determine whether a sequential stopping rule makes the permutation test faster without degrading detection.
\end{enumerate}

\section{Scope of the Study}
This thesis studies unsupervised detection of feature drift, that is, changes in the input distribution $P(X)$, in data streams with numerical features. Labels are not used for detection, so changes in $P(y \mid X)$ that leave $P(X)$ unchanged are outside the scope. The evaluation uses thirteen real-world data streams from the benchmark of \citet{Lukats2024}: four INSECTS streams with annotated drift points \citep{Souza2020} and nine streams without annotations. EADD is compared with D3, run with the same LightGBM classifier and window sizes as EADD, and with six other unsupervised detectors from the benchmark. Synthetic data streams are not used. The TreeSHAP feature ranking that EADD reports with each detection is described but its accuracy is not evaluated, and drift adaptation, such as retraining the deployed model, is not studied.

\section{Assumptions}
The study relies on the following assumptions:
\begin{enumerate}
    \item The reference window contains data from the distribution that is considered normal, so that a difference between the reference and current windows indicates drift.
    \item Under the null hypothesis of no drift, the samples in the reference and current windows are exchangeable. The permutation test is only valid under this assumption, which is violated when consecutive samples are correlated.
    \item The drift points annotated in the INSECTS streams \citep{Souza2020} mark the true changes in their distributions.
\end{enumerate}

\section{Definitions of Terms}
\begin{description}
    \item[Feature drift (covariate drift):] a change over time in the distribution of the input features $P(X)$.
    \item[Concept drift:] a change over time in the conditional distribution $P(y \mid X)$.
    \item[Classifier two-sample test (C2ST):] a test of whether two samples come from the same distribution, based on how well a classifier can tell them apart \citep{LopezPazOquab2017}.
    \item[Adversarial validation:] the practice of training a classifier to separate two data sets, such as training data and production data, and reading a high AUC as evidence that they differ \citep{Pan2020}. As a statistical test, it is a C2ST.
    \item[Reference window and current window:] the baseline sample $W_{ref}$ and the most recent sample $W_{cur}$ that a drift detector compares.
    \item[AUC:] the area under the receiver operating characteristic curve of the classifier that separates the two windows; 0.5 means the windows cannot be separated.
    \item[Permutation test:] a test that compares the observed AUC with the AUCs obtained after randomly shuffling the window labels.
    \item[Recall:] the proportion of annotated drift points that are detected within the tolerance window of 500 samples after them.
    \item[Mean time to detection (MTD):] the average number of samples between an annotated drift point and its first matching detection, where a drift point that is not detected counts as 500 samples, the length of the tolerance window.
    \item[False alarm:] a detection that does not fall within the tolerance window of an annotated drift point.
    \item[Lift-per-drift:] the gain in accuracy of a classifier that is reset at every detection over a classifier trained only at the start of the stream, divided by the number of detections \citep{Lukats2024}.
\end{description}

\section{Research Contribution}
This thesis makes the following contributions:

\begin{enumerate}
    \item We propose EADD, an integrated framework for unsupervised feature drift detection that combines a classifier two-sample test, a reservoir-sampled reference window, prediction entropy monitoring and an adaptive sequential permutation test, and that ranks the features behind each confirmed drift.

    \item We add a sequential stopping rule, motivated by sequential Monte Carlo tests \citep{Gandy2009}, to the permutation test of the classifier two-sample test. On four annotated real-world streams, ASPT gave the same detections as a full permutation test in all 20 runs with 25\% less runtime, and at low AUC thresholds it reduced false alarms by up to 81\% compared with no test. A simulation shows that the rule raises the Type~I error of a single test from 0.045 to 0.059 at $\alpha = 0.05$.

    \item We compare EADD with D3 and six other unsupervised detectors on thirteen real-world data streams, with D3 using the same classifier and window sizes as EADD, and test the differences for statistical significance.
\end{enumerate}

\chapter{Literature Review} \label{chap:literature}


\section{Overview}
Drift detection addresses the challenge that arises when the statistical characteristics of data evolve over time in a manner that impacts the validity of a machine learning model \citep{Lu2018, Gama2014}. According to \citet{Bayram2022}, when users, environments, data sources, or the relationships between labels and features change, model accuracy can diminish. \citet{Gama2014} and \citet{Sculley2015} emphasise that drift detection identifies such modifications early, allowing practitioners to adapt, retrain, or update the model accordingly. A robust understanding of drift types and detection methods is essential for designing effective monitoring systems. Figure~\ref{fig:feature-drift} illustrates the idea behind the discriminative detectors studied in this thesis: when the reference and current distributions overlap, a classifier cannot tell their samples apart, and when the distribution shifts, it can.

\section{Types of Drift}
Drift can be categorised along two main dimensions: by the nature of the change (what component of the data-generating process is affected) and by the temporal pattern of the change (how the drift manifests over time) \citep{Lu2018, Gama2014}.

\subsection{Drift by Nature of Change}
Based on which component of the joint distribution $P(X, y)$ changes, the literature \citep{Lu2018, Gama2014, Tsymbal2004} classifies drift into the following types:

\textbf{Concept Drift (Real Drift):} The conditional distribution $P(y|X)$ changes over time while the feature distribution $P(X)$ may or may not change \citep{Lu2018, Zliobaite2010}. This represents a change in the underlying relationship between inputs and outputs: the ``concept'' the model has learned becomes invalid. For example, the factors that determine creditworthiness may evolve due to economic shifts, even if the applicant characteristics (features) remain similar \citep{Gama2014}. Concept drift directly degrades model performance because the learned decision boundaries no longer reflect the true input-output relationship \citep{Lu2018}.

\textbf{Covariate Drift (Feature Drift / Virtual Drift):} The marginal distribution of input features $P(X)$ changes over time while the conditional relationship $P(y|X)$ remains stable \citep{Tsymbal2004, Shimodaira2000}. The ground-truth concept does not change, but the model may encounter inputs outside its training distribution. For example, a fraud detection model trained on transaction patterns from one demographic may receive data from a different user population, even though the definition of fraud remains unchanged \citep{Tsymbal2004}. Covariate drift can degrade model performance because the model is exposed to feature regions where it may not generalise well \citep{Shimodaira2000}.

\textbf{Prior Probability Drift (Label Shift):} The marginal distribution of labels $P(y)$ changes over time while $P(X|y)$ remains stable \citep{Tsymbal2004}. This occurs when the prevalence of different classes changes, for instance a seasonal increase in a particular disease that alters the class balance in medical diagnosis. This is sometimes called class imbalance shift \citep{Lu2018}.

\textbf{Note on Terminology:} The literature uses varied terminology \citep{Lu2018}. The term ``concept drift'' is sometimes used as an umbrella term for any distribution change affecting model performance \citep{Gama2014}, while some reserve it specifically for changes in $P(y|X)$ \citep{Tsymbal2004}. This thesis focuses primarily on covariate (feature) drift detection, as it enables early warning without requiring labels.

\subsection{Drift by Temporal Pattern}
Based on how drift manifests over time, the literature \citep{Lu2018, Gama2014, Zliobaite2010} categorises drift as follows:

\begin{itemize}
    \item \textbf{Abrupt (Sudden) Drift:} A rapid, discrete change where the data distribution shifts quickly from one state to another within a short time period \citep{Gama2014}.

    \item \textbf{Gradual Drift:} A new distribution progressively replacing the old one over an extended duration, with samples from both distributions interleaved during the transition period \citep{Lu2018}.

    \item \textbf{Incremental Drift:} Small but continuous changes accumulating over time, eventually resulting in a significant distributional shift \citep{Zliobaite2010}.

    \item \textbf{Recurring (Seasonal) Drift:} Previously observed distributions reappearing periodically due to cyclical patterns, such as seasonal effects in retail or recurring user behaviour patterns \citep{Lu2018, Gama2014}.
\end{itemize}

Understanding drift patterns is important for detector design: abrupt drift requires rapid response, gradual drift requires sustained sensitivity, and recurring drift benefits from mechanisms that can recognise previously seen distributions \citep{Gama2014}.

\section{Classification of Drift Detection Methods}
Based on surveys of the drift detection literature \citep{Lu2018, Gama2014, Tsymbal2004, Hinder2024}, drift detection methods can be classified along several dimensions. According to \citet{Lu2018}, the most fundamental distinction is based on label availability: whether the method requires access to ground-truth labels (supervised) or operates without them (unsupervised).

\subsection{Supervised Drift Detection Methods}
Supervised detectors require ground-truth labels and monitor the error stream of the deployed model \citep{Gama2014, Gama2004}. They assume that a change in error behaviour, such as a higher error rate, errors that occur closer together, or a shift in the mean of a monitored loss, indicates drift \citep{Gama2004, BaenaGarcia2006}. The methods in this group differ mainly in the statistic they track and in the bound they use to decide that a change is significant. DDM compares the error rate and its standard deviation with thresholds derived from the binomial distribution \citep{Gama2004}. EDDM tracks the distance between consecutive errors, which makes it more sensitive to gradual drift \citep{BaenaGarcia2006}. The Page--Hinkley test accumulates the deviations of the monitored signal from its mean \citep{Page1954}, and HDDM-A and HDDM-W replace distributional assumptions with Hoeffding's inequality, using moving averages for abrupt change and weighted windows for gradual change \citep{FriasBlanco2015}.

Because these methods all watch the model's errors, they share the same strengths and weaknesses. Their alarms are tied directly to model performance, and their thresholds have a clear statistical meaning. However, they need labels, which are often delayed, expensive, or unavailable in production \citep{Lu2018, Sethi2017}. They also react only after drift has already degraded performance, and they cannot detect a change in $P(X)$ that has not yet affected the error rate.

\subsection{Unsupervised Drift Detection Methods}
Unsupervised drift detection methods do not require ground-truth labels and instead monitor changes in data distribution, model outputs, or internal representations \citep{Tsymbal2004, Hinder2024}. These methods enable earlier detection of distributional shifts, before performance degradation becomes observable, which makes them valuable in production environments with label delays \citep{Sethi2017}.

\subsubsection{Statistical Distribution-Based Methods}
Statistical methods compare a reference window with a current window through hypothesis tests or distance measures \citep{Rabanser2019, Raab2020, BifetGavalda2007}. They differ in what they compare. ADWIN compares the means of sub-windows of an adaptive window and shrinks the window when they differ, with guarantees on its false positive and false negative rates \citep{BifetGavalda2007}. KSWIN applies the Kolmogorov--Smirnov test to one feature at a time over sliding windows \citep{Raab2020}, and chi-squared tests play the same role for categorical or discretised features \citep{Lu2018}. Divergence measures such as the Kullback--Leibler divergence, the Jensen--Shannon divergence and the Hellinger distance quantify how far apart two estimated distributions are \citep{Dasu2006, DitzlerPolikar2011}, while the Maximum Mean Discrepancy (MMD) compares whole multivariate distributions through kernel embeddings \citep{Gretton2012}.

As a group, these methods are label-free, theoretically grounded and easy to interpret \citep{Rabanser2019}. Most of them, however, test one feature at a time. With $d$ features this requires $d$ tests, so unless the significance level is corrected, the probability of at least one false alarm grows with $d$, and changes in the joint distribution that leave every marginal unchanged are missed \citep{Lu2018, Webb2016}. Multivariate tests such as MMD avoid the per-feature problem, but their power depends on the choice of kernel \citep{Gretton2012}.

Because PSI and the KS test are univariate, monitoring $d$ features requires $d$ separate tests. The discriminative approach instead tests the joint distribution of all $d$ features with a single classifier.

\subsubsection{Model-Based Discriminative Methods}
Discriminative methods train an auxiliary classifier to tell reference samples from current samples \citep{LopezPazOquab2017, Pan2020, Sethi2017}. If the classifier separates the two sets better than chance, the distributions differ. The methods in this group differ in what they read from the classifier. Domain classifiers, also called adversarial validation in industry practice, use the accuracy or AUC of a logistic regression, random forest, or gradient boosting model trained on the two windows \citep{Pan2020, Qian2021}. D3 applies this idea to data streams with a logistic regression classifier and a fixed AUC threshold \citep{Gozuacik2019}, and it is one of the three detectors recommended by a recent benchmark \citep{Lukats2024}. Margin density methods such as MD3 instead track the proportion of samples that fall close to the decision boundary of a classifier \citep{Sethi2017}.

The main strength of the group is that one classifier tests all features jointly and can capture non-linear changes that marginal tests miss \citep{LopezPazOquab2017}. No labels are needed, only the window that each sample came from \citep{Pan2020}. The costs are that a classifier must be trained at every monitoring step, that the results depend on the classifier and its hyperparameters, and that a raw AUC or margin value has no statistical calibration unless a test, such as a permutation test, is added \citep{Sethi2017, LopezPazOquab2017}.

\subsubsection{Representation-Based Methods}
Representation-based methods monitor learned representations rather than raw features \citep{Rabanser2019, Liu2020}. They compute distances such as the Wasserstein distance or MMD between reference and current embeddings taken from intermediate layers of a neural network \citep{Rabanser2019}, or they track the stability of learned representations using ideas from domain adaptation and transfer learning \citep{Long2016}. These methods suit deep learning systems in which raw feature distributions do not reflect semantically meaningful changes \citep{Liu2020}, but they require a representation model and are less relevant for the tabular streams studied in this thesis.

\subsubsection{Prediction-Based and Output-Based Methods}
Prediction-based methods monitor the outputs of the deployed model without checking whether they are correct \citep{Sethi2017, Gozuacik2019}. They track the distribution of predicted classes or scores \citep{Gozuacik2019}, or the entropy and confidence of the predictions, under the assumption that rising uncertainty indicates out-of-distribution inputs \citep{Guo2017}. Their weakness is calibration: modern models, deep networks in particular, are often poorly calibrated, and under distribution shift their confidence may not change in step with their errors \citep{Guo2017, Ovadia2019}. The prediction entropy signal used in EADD (Chapter~\ref{chap:methodology}) differs from these methods because it is computed from the discriminator that separates the two windows, not from the deployed model.

\subsubsection{Unsupervised Detectors Evaluated in Recent Benchmarks}
\citet{Lukats2024} reviewed ten fully unsupervised drift detectors and evaluated seven of them on eleven real-world data streams; the other three were too slow or depended too much on chance. They also found that the size of the observed samples was one of the most influential hyperparameters. The detectors they studied can be grouped by the mechanism they use.

The discriminative group is represented by D3 \citep{Gozuacik2019}, which achieved the best mean time ratio in the benchmark but, like the other detectors, reports only that drift occurred \citep{Lukats2024}.

Clustering-based detectors summarise each window with clusters and test whether the clusters change. CSDDM reduces dimensionality with PCA, clusters the data with K-Means, and applies statistical tests to the clusters \citep{CSDDM2021}, while UCDD assigns pseudo-labels from cluster membership and monitors shifts of the cluster boundary \citep{UCDD2020}. CSDDM was among the detectors that performed well on the benchmark's lift-per-drift metric, which measures how much classifier accuracy improves per detected drift \citep{Lukats2024}.

Density-based detectors model the reference distribution and flag new data that fit the model poorly. SPLL fits a semi-parametric density model and monitors the log-likelihood of new observations \citep{SPLL2013}, NN-DVI tracks changes in nearest-neighbour density \citep{NNDVI2018}, OCDD fits a one-class SVM to the reference data and counts the samples that fall outside its boundary \citep{OCDD2021}, and BNDM compares windows with a Bayesian non-parametric P\'{o}lya tree test \citep{BNDM2020}. These detectors respond well to sudden changes in density, but they are sensitive to the size of the reference sample: BNDM signalled drift periodically when it observed few samples, and many OCDD configurations showed the same periodic behaviour \citep{Lukats2024}.

A last group reduces the stream to a simpler signal. IBDD converts windows of numerical data into images and compares the images \citep{IBDD2021}, and UDetect applies Shewhart control charts to the standard deviation of each window. IBDD achieved the best classifier accuracy in the benchmark because it can signal drift again immediately after a reset, but it was among the worst detectors on mean time ratio, and 45\% of the UDetect configurations detected no drift at all \citep{Lukats2024}.

Across these groups, the benchmarked detectors report whether drift occurred but not where it occurred \citep{Lukats2024}. D3 is the only discriminative detector in the benchmark, and it relies on a fixed AUC threshold rather than a calibrated test.

\subsection{Hybrid and Ensemble Methods}
Hybrid approaches combine several sources of information, such as model predictions, embeddings, operational signals and metadata, into a single context-weighted drift score, while ensemble approaches combine several base detectors through voting, weighting, or meta-learning to reduce both false alarms and missed detections \citep{Gama2014, Krawczyk2017}. These approaches can be more robust than any single detector, but they inherit the label or context requirements of their components, and misspecified context can cause missed detections or spurious alarms \citep{Krawczyk2017}.

\section{Limitations of Existing Methods}
Each group of methods has characteristic limitations. Supervised methods need timely labels and detect drift only after performance has degraded \citep{Lu2018, Sethi2017}. Statistical tests are sensitive to noise, mostly test marginal distributions, and raise more false alarms as the number of tested features grows \citep{Rabanser2019, Lu2018, Webb2016}. Prediction-based and uncertainty-based methods depend on model calibration, which is often poor under distribution shift \citep{Guo2017, Ovadia2019}, and context-aware methods depend on context variables that may be incomplete or may drift themselves \citep{Krawczyk2017}.

Discriminative tests avoid several of these problems. They test the joint feature distribution directly, need neither labels nor calibrated model outputs, and make no assumption about which features matter \citep{LopezPazOquab2017, Pan2020}. In streaming drift detection, however, they have mostly been used with fixed thresholds, as in D3 \citep{Gozuacik2019}.

\section{Drift Mitigation and Adaptation Strategies}
\label{sec:mitigation}
Detecting drift is only the first step; production systems must also respond to it. The literature describes five principal mitigation strategies, each with distinct trade-offs \citep{Lu2018, Gama2014, Krawczyk2017}:

\begin{enumerate}
    \item \textbf{Periodic Retraining:} The model is retrained on the latest data at fixed intervals (e.g., weekly or monthly) or triggered by drift alerts. This is the most common industrial approach because of its operational simplicity, but fixed schedules may retrain unnecessarily or react too slowly \citep{Gama2014}.

    \item \textbf{Weighted Retraining:} Old and new data are combined for retraining, but recent examples receive higher weights. This preserves long-term knowledge while prioritising current patterns, and is particularly effective for gradual drift \citep{Krawczyk2017}.

    \item \textbf{Ensemble Methods:} A library of models (for example, one per season or data regime) is maintained, and predictions are combined via voting, stacking, or dynamic weighting. When drift is detected, poorly performing members are discarded and new ones trained on the current distribution \citep{Krawczyk2017}.

    \item \textbf{Online / Incremental Learning:} The model is updated continuously as each new data point (or mini-batch) arrives, making it naturally adaptive to gradual and incremental drift. This is common in streaming applications such as fraud detection and recommendation systems \citep{Gama2014, Ditzler2015}.

    \item \textbf{Human-in-the-Loop:} Uncertain or drifted samples are routed to human experts for re-labelling, which feeds into the next training iteration. This strategy is essential in domains where errors carry high cost (e.g., healthcare, autonomous driving) and labelling is expensive \citep{Lu2018}.
\end{enumerate}

\section{Discriminative and Attribution Approaches}

\subsection{Discriminative Distribution Testing}
Discriminative approaches to distribution comparison reframe the problem as a binary classification task: a classifier is trained to predict whether each instance originates from a reference distribution or a target distribution. High discriminative performance (AUC $\gg 0.5$) indicates the distributions are statistically separable; near-random performance suggests they are indistinguishable \citep{Pan2020, Qian2021}.

\citet{Pan2020} used this approach at Uber for the MaLTA user targeting system, training a classifier to detect mismatch between training and deployment data and retraining when the two were strongly separable. \citet{Qian2021} applied discriminative testing to manage dataset shift in credit scoring. D3 \citep{Gozuacik2019} turned the idea into a streaming detector that trains logistic regression classifiers on sliding windows and signals drift when the AUC exceeds a fixed threshold of 0.7. D3 achieved the best mean time ratio in the \citet{Lukats2024} benchmark. However, D3 applies no formal significance test, so its fixed threshold has no statistical calibration.

The \textit{classifier two-sample test} (C2ST), formalised by \citet{LopezPazOquab2017}, provided theoretical foundations for the discriminative approach: significance is calibrated via permutation testing, allowing principled Type~I error control. The approach is label-independent, model-agnostic, and makes no assumptions about which features are important. \citet{EC2ST2024} extended C2ST with anytime-valid e-values for sequential monitoring, and \citet{MCD2024} proposed Maximum Concept Discrepancy, which uses contrastive learning as an alternative to classifier-based testing for online drift detection. C2ST and E-C2ST were designed for distribution testing rather than for streaming drift detection, and neither provides feature-level attribution of the detected shift.

D3 and other C2ST-based streaming detectors usually discard the trained classifier after computing the AUC. Practitioners therefore learn whether drift occurred but receive no guidance on which features caused it, even though the classifier has learned which features separate the two windows.

\subsection{Drift Localisation}
Drift localisation asks where a drift occurs \citep{HinderLocalization2024}. The question can be posed for regions of the data space, that is, which samples are affected, or for features, that is, which input dimensions are affected. \citet{HinderLocalization2024} formalise localisation as finding the smallest region of the data space whose removal leaves no drift, and they survey the methods that address it. Most of these methods are built on local drift detection. Binning methods such as kdq-trees partition the data space and compare the samples in each cell \citep{Dasu2006}. Neighbourhood methods compare the local density around each sample, as in the local drift degree of \citet{Liu2017LDD}. Model-based methods train a probabilistic classifier to separate time periods and read the affected regions from its predictions \citep{HinderLocalization2024}.

Feature-level localisation has developed alongside this work. \citet{Kulinski2020} framed the question of which features have shifted as a set of conditional distribution tests, one per feature, and proposed parametric and non-parametric versions based on the score function of a density model. \citet{HinderFeature2024} gave formal definitions of feature-wise drift that allow detector-agnostic selection of drifting features. TRIPODD \citep{TRIPODD2024} tests pre-specified feature interactions with power guarantees, at a cost that grows quadratically with the number of features.

Localisation methods therefore already exist for samples, regions and features. They differ in what they require: a density model \citep{Kulinski2020}, pre-specified interactions \citep{TRIPODD2024}, or batch access to the data \citep{HinderFeature2024}. A further option, discussed next, is to explain the classifier that a discriminative test has already trained.

\subsection{Feature Attribution for Drift Detection}
Feature attribution methods explain the output of a model in terms of its input features. SHAP assigns each feature its Shapley value \citep{Shapley1953} in a cooperative game whose players are the features \citep{Lundberg2017}, and TreeSHAP computes these values exactly and in polynomial time for tree ensembles \citep{LundbergInteraction2020}. Attribution has been connected to drift in two main ways.

The first way explains a domain classifier. \citet{Maggio2021} trained a classifier to separate old data from new data and ranked the features by the mean absolute SHAP value of the classifier's output. In that study, the SHAP ranking identified the corrupted features more reliably than the classifier's impurity-based feature importance. This is the same classifier that a discriminative drift detector already trains, so the ranking adds feature-level localisation at little extra cost. Its limitations come from SHAP itself: the attributions describe the classifier rather than the data-generating process, and they are correlational rather than causal \citep{CausalDrift2025}.

The second way monitors the attributions of the deployed model. \citet{LundbergInteraction2020} monitored the SHAP values of a deployed model over time to find problems in its data pipeline. \citet{Mougan2025} defined explanation shift as a change in the distribution of a model's explanations between training data and new data, and showed that it can reveal shifts that change model behaviour, including changes in feature interactions that per-feature distribution tests miss. Commercial monitoring services follow the same idea: Google Vertex AI and Amazon SageMaker Clarify compare the feature attributions of production predictions with a baseline computed during training \citep{TalySato2021, AWSSageMaker2025}.

A related line of work attributes changes in model performance, rather than changes in the data distribution, to features or to parts of the data-generating process. \citet{Zhang2023Attribution} treated the distributions that make up the data-generating process as players in a cooperative game and attributed a model's performance change to them with Shapley values. HDPD decomposes a performance gap into covariate and conditional components with per-feature attributions \citep{HDPD2024}, DBShap separates virtual and real drift with distributional Shapley values \citep{DBShap2024}, and XPE combines optimal transport with Shapley values to explain how feature shifts affect performance \citep{XPE2024}. These methods require labels. A recent systematic review found that most work on explaining drift adapts static explanation methods to streaming data without addressing scalability or interactions between features \citep{XAIDriftSurvey2025}.

SHAP-based ranking of the features that separate two windows has therefore been used before \citep{Maggio2021}. This thesis does not claim it as a contribution; EADD uses it as one component of the framework.

\subsection{Other Recent Directions}
Other recent work has addressed label efficiency, explanation quality and robustness. Semi-supervised and student--teacher methods reduce or remove the need for labels \citep{CDSeer2024, STUDD2022}, per-label embedding monitoring extends drift detection to unstructured data \citep{DriftLens2024}, and autoregressive error monitoring adds confidence intervals to supervised detection \citep{ADDM2022}. For explanations, SGShift characterises concept shift with generalised additive models and controls the false discovery rate with knockoffs \citep{SGShift2025}, and \citet{CausalDrift2025} argue that drift explanations need causal rather than correlational attribution to guide remediation. \citet{AdvAttackDrift2024} showed that adversarially constructed data streams can evade common drift detectors, including discriminative ones.

\section{Gap in the Literature}
The review shows that the components of a discriminative drift detector that is both calibrated and interpretable already exist, but they have not been combined and evaluated together in a streaming setting. A classifier two-sample test can be calibrated with a permutation test \citep{LopezPazOquab2017}, but a fixed-budget permutation test retrains the classifier many times at every alarm, and D3, which a recent benchmark recommends, uses an uncalibrated fixed threshold instead \citep{Gozuacik2019, Lukats2024}. Sequential stopping rules that preserve the Type~I error of Monte Carlo tests \citep{Gandy2009} have not, to our knowledge, been applied to discriminative drift detection, and e-value tests \citep{EC2ST2024} were designed for distribution testing rather than for streaming detection.

A second gap concerns how discriminative detectors are compared. A new discriminative detector usually differs from D3 in its classifier, its window sizes, and the way it maintains its reference data. A comparison that changes all of these at once cannot show which of them causes the differences in detection delay, missed drifts and false alarms. Finally, feature-level localisation methods \citep{Kulinski2020, HinderFeature2024, TRIPODD2024} and SHAP explanations of domain classifiers \citep{Maggio2021, Mougan2025} answer the question of which features drifted, but they are usually run separately from, and after, detection.

This thesis addresses these gaps with EADD, an integrated framework that combines a LightGBM classifier two-sample test, a reservoir-sampled reference window, prediction entropy monitoring and an adaptive sequential permutation test, and that reports a TreeSHAP feature ranking for every confirmed drift. The evaluation compares EADD with a version of D3 that uses the same classifier and window sizes, so that only the reference memory and the decision rule differ.

\section{Research Questions}
\label{sec:rq}

Based on the gaps identified in Chapter~\ref{chap:literature}, this thesis investigates three research questions:

\begin{itemize}
    \item \textbf{RQ1:} Does EADD detect annotated drifts in real-world data streams more completely and sooner than D3, and does it raise fewer false alarms?

    \item \textbf{RQ2:} Does the sequential stopping rule of ASPT make the permutation test faster without degrading detection, and how does the AUC threshold affect EADD?

    \item \textbf{RQ3:} How do EADD and the other detectors behave on real-world streams without annotated drift points?
\end{itemize}

\section{Hypotheses}
\label{sec:hypotheses}

Three hypotheses are tested at $\alpha = 0.05$ with the tests described in Section~\ref{sec:stats}:

\begin{itemize}
    \item \textbf{H1 (Detection):} On the annotated streams, EADD detects drifts more completely and sooner than D3. H1a states that the recall of EADD is higher than that of D3, and H1b that the MTD of EADD is lower than that of D3.

    \item \textbf{H2 (False Alarms):} On the annotated streams, EADD raises fewer false alarms than D3. Formally, $H_0$: $\text{FA}_{\text{EADD}} \geq \text{FA}_{\text{D3}}$ versus $H_1$: $\text{FA}_{\text{EADD}} < \text{FA}_{\text{D3}}$, where FA is the number of false alarms in a run.

    \item \textbf{H3 (ASPT):} ASPT does not degrade detection and runs faster than a full permutation test. H3a states that the recall, MTD and false alarms of EADD with ASPT do not differ from those of EADD with a full permutation test, and H3b that EADD with ASPT has a lower runtime.
\end{itemize}

H1 and H2 answer RQ1, and H3 answers RQ2. RQ3 is answered descriptively, because the streams it uses have no annotated drift points to test against.

\section{Changes from the Thesis Proposal}
\label{sec:proposal-changes}

The thesis proposal planned to study adversarial validation as a feature drift detection technique, using a logistic regression or random forest classifier, a permutation test with 200 permutations, and a rule that signals drift when the AUC is at least 0.7 and the p-value is below 0.05. It asked how effective adversarial validation is for different drift types, whether it detects drift earlier than statistical and error-based methods, and how it compares with PSI, the KS test, DDM and ADWIN. This thesis keeps that goal but changes three parts of the plan.

First, the detector was developed into EADD. The classifier was changed to LightGBM, the sliding reference window to a reservoir sample, and the fixed-budget permutation test to a sequential one, and a feature ranking was added. D3 \citep{Gozuacik2019}, a published streaming detector based on the same principle, became the main baseline. It is run with the same LightGBM classifier and window sizes as EADD, so that these choices do not confound the comparison.

Second, the baselines were changed. DDM monitors the error rate of a deployed model and therefore needs labels, while PSI, the KS test and ADWIN monitor one variable at a time. Comparing them with a multivariate unsupervised detector would require choices that are not part of these methods, such as which variable to monitor and how to combine the tests for each feature. The thesis therefore compares EADD with D3 and with six fully unsupervised detectors of the \citet{Lukats2024} benchmark, which take the same multivariate input as EADD and have tested implementations. PSI and the KS test are discussed in Chapter~\ref{chap:literature}.

Third, the proposal's questions about drift types and early detection are answered on real-world streams with annotated drift points instead of synthetic streams. Comparison with error-based detectors, which need labels, is outside the scope of the thesis.

\section{The EADD Framework}
\label{sec:eadd}
EADD treats feature drift ($P(X)$ shift) detection as binary classification: if a classifier can reliably distinguish reference data from current data based solely on features, the distributions have diverged \citep{LopezPazOquab2017, Gozuacik2019}. D3 \citep{Gozuacik2019} uses this principle with a fixed AUC threshold, and \citet{LopezPazOquab2017} showed how to calibrate the test with permutations. EADD combines these ideas with a long-memory reference window, a sequential version of the permutation test, and a feature ranking for each confirmed drift.

\subsection{Problem Formulation}
\label{sec:problem}
Let $\{x_t\}_{t=1}^{T}$, with $x_t \in \mathbb{R}^d$, denote a stream of feature vectors. At each monitoring point $t$, a detector compares two windows:
\begin{itemize}
    \item a reference window $W_{ref}$ of $N_{ref}$ samples, assumed to represent the baseline feature distribution $P_{ref}(X)$, and
    \item a current window $W_{cur}$ containing the $N_{cur}$ most recent samples, drawn from the current distribution $P_{cur}(X)$.
\end{itemize}
Feature drift at time $t$ means $P_{cur}(X) \neq P_{ref}(X)$. The detector therefore tests
\begin{equation}
H_0: P_{ref}(X) = P_{cur}(X) \quad \text{versus} \quad H_1: P_{ref}(X) \neq P_{cur}(X)
\label{eq:drift-test}
\end{equation}
and outputs a decision $d_t \in \{0, 1\}$, where $d_t = 1$ signals drift. In EADD, the test statistic is the cross-validated AUC of a classifier $f_\theta$ trained to separate $W_{ref}$ from $W_{cur}$. The symbol $\tau$ denotes the AUC screening threshold, $\alpha$ the significance level, and $B_{\min}$ and $B_{\max}$ the minimum and maximum numbers of permutations used by the permutation test.

Figure~\ref{fig:methodology-detailed-architecture} shows the steps of EADD, and Table~\ref{tab:eadd-alignment} lists the methods each step builds on.

\subsection{Step 1: Adaptive Reference Windowing}
To detect feature drift, the current data must be compared against a stable baseline. EADD maintains two windows consistent with established methodologies \citep{BifetGavalda2007, Tsymbal2004}:

\textbf{Reference Window ($W_{ref}$):} A buffer containing $N_{ref}$ historical samples representing the stable feature distribution $P_{ref}(X)$. Unlike sliding windows, which forget older data quickly, EADD uses \textbf{reservoir sampling} \citep{Vitter1985} so that the reference represents all samples seen since the last confirmed drift, not just the most recent batches.

\textbf{Current Window ($W_{cur}$):} A buffer containing the $N_{cur}$ most recent observations representing the current feature distribution $P_{cur}(X)$. As new data arrives, older samples are discarded to maintain responsiveness to recent changes.

\textbf{Update Mechanism:} At each monitoring step:
\begin{itemize}
    \item New samples enter $W_{cur}$
    \item Oldest samples exit $W_{cur}$
    \item Reservoir sampling maintains representative $W_{ref}$
    \item Upon confirmed drift, $W_{ref}$ is reset to the current window
\end{itemize}

According to \citet{Lu2018}, window sizes represent a bias-variance tradeoff: larger windows provide more stable estimates but slower response; smaller windows enable faster detection but higher variance.

\subsection{Step 2: Discriminative Classification}
This step implements the \textbf{classifier two-sample test} (C2ST) \citep{LopezPazOquab2017}, also referred to as ``discriminative classification'' or ``adversarial validation'' in industry practice \citep{Pan2020}, which forms the foundation of both D3 \citep{Gozuacik2019} and EADD. The question it asks is whether a model can tell the difference between old and new data.

\textbf{Construct Binary Classification Dataset:}
\begin{itemize}
    \item Label all samples from $W_{ref}$ as class 0 (``old'' / reference)
    \item Label all samples from $W_{cur}$ as class 1 (``new'' / current)
    \item Combined dataset: $X = W_{ref} \cup W_{cur}$, $y = \{0\}^{N_{ref}} \cup \{1\}^{N_{cur}}$
\end{itemize}

\textbf{Train Discriminative Classifier:}
A binary classifier $f_\theta$ is trained to predict the data source from the features alone. EADD uses \textbf{LightGBM} \citep{Ke2017}, a gradient boosting decision tree ensemble, as the default classifier. D3 \citep{Gozuacik2019} uses logistic regression, which can only separate the windows with a linear boundary; LightGBM can also capture non-linear differences and feature interactions. D3-LightGBM, the version of D3 used in this thesis, uses the same classifier.

\textbf{Measure Discriminative Performance:}
Classifier performance is evaluated with stratified 5-fold cross-validation:
\begin{itemize}
    \item \textbf{AUC-ROC:} the primary metric, the area under the ROC curve
    \item AUC $\approx$ 0.5: the classifier cannot distinguish $W_{ref}$ from $W_{cur}$ $\rightarrow$ \textbf{no feature drift}
    \item AUC $\gg$ 0.5: the classifier separates the windows $\rightarrow$ $P_{ref}(X) \neq P_{cur}(X)$ $\rightarrow$ \textbf{feature drift suspected}
\end{itemize}

If the AUC exceeds the screening threshold $\tau$, the alarm is passed to the significance test in Step~3. The term ``adversarial'' in EADD's name refers to this C2ST setting, in which a classifier is trained to distinguish two data sources, and not to adversarial attacks in the security or robustness sense.

\subsection{Step 2b: Prediction Entropy Monitoring ($H_{\text{pred}}$)}
After training the discriminative classifier (Step~2), EADD computes the \textbf{prediction entropy} $H_{\text{pred}}$ as an early-warning signal for distributional instability. This is the binary Shannon entropy \citep{Shannon1948} of the C2ST discriminator's output probabilities, averaged over all samples:

\begin{equation}
H_{\text{pred}} = \frac{-1}{n} \sum_{i=1}^{n} \left[\hat{p}_i \ln \hat{p}_i + (1 - \hat{p}_i) \ln (1 - \hat{p}_i)\right]
\label{eq:hpred}
\end{equation}

where $\hat{p}_i = f_\theta(x_i)$ is the discriminative classifier's predicted probability that sample $i$ belongs to the current window ($W_{cur}$), and $n = |W_{ref}| + |W_{cur}|$ is the combined sample count.

\textbf{Interpretation:}
\begin{itemize}
    \item $H_{\text{pred}} \approx \ln 2$: Maximum entropy; the classifier cannot distinguish windows $\rightarrow$ no distributional difference
    \item $H_{\text{pred}} \rightarrow 0$: Low entropy; the classifier clearly separates windows $\rightarrow$ strong drift signal
    \item Intermediate $H_{\text{pred}}$: Subtle distributional change that may not yet reach statistical significance
\end{itemize}

\textbf{Monitoring Property:}
$H_{\text{pred}}$ is computed at every monitoring step, including steps where the AUC has not yet reached $\tau$, so it gives a continuous view of how confidently the discriminator separates the two windows. It was intended as an early-warning signal for gradual and incremental drift, but this thesis does not evaluate it as one. A quantitative evaluation, including threshold selection and the precision and recall of pre-alarm warnings, is left to future work.

\textbf{Relationship to AUC:}
$H_{\text{pred}}$ and AUC are complementary signals. AUC measures overall discriminability, while $H_{\text{pred}}$ measures the confidence distribution of individual predictions. A high AUC with low entropy indicates clear, systematic drift; a moderately elevated AUC with higher entropy may indicate localised or emerging drift affecting only a subset of samples.

\subsection{Step 3: Adaptive Sequential Permutation Test (ASPT)}
A raw AUC score (e.g., 0.65) is inconclusive, as it may reflect genuine distributional change or statistical noise. D3 \citep{Gozuacik2019} relies on a fixed threshold (AUC $> 0.7$) without a significance test. \citet{LopezPazOquab2017} proposed the classifier two-sample test (C2ST) with significance testing, typically implemented as a fixed-budget permutation test \citep{Good2005} with a predetermined number $B$ of permutations.

\textbf{The Computational Problem:} A fixed-budget permutation test (e.g., $B=50$) wastes computation when the evidence is clear. If the actual AUC is 0.95, the first few permutations already establish significance and the remaining permutations add cost without information. Conversely, if the AUC is 0.52, early permutations quickly reveal non-significance.

\textbf{Adaptive Sequential Permutation Testing:}
EADD uses an \textbf{adaptive sequential permutation test} motivated by the sequential Monte Carlo tests of \citet{Gandy2009}. Gandy's algorithm uses stopping boundaries that bound the probability of reaching a different decision than the exact test would; ASPT instead uses two simple stopping rules. Instead of committing to a fixed budget $B$, ASPT checks the evidence after each permutation and stops early when one of the rules applies:

\begin{enumerate}
    \item \textbf{Initialise:} Set maximum budget $B_{\max}$, nominal significance level $\alpha$, and minimum sequential budget $B_{\min}$.
    \item \textbf{Sequential Execution:} For each permutation $i = 1, \ldots, B_{\max}$:
    \begin{itemize}
        \item Shuffle labels, retrain the discriminative classifier, compute $\text{AUC}^{(i)}_{\text{perm}}$ with 2-fold cross-validation
        \item Update running count: $c_i = \#\{j \leq i : \text{AUC}^{(j)}_{\text{perm}} \geq \text{AUC}_{\text{actual}}\}$
        \item \textbf{Early reject $H_0$ (confirm drift):} If $c_i = 0$ and $i \geq B_{\min}$ and the conservative bound $1/(i+1) < \alpha$ holds, terminate and confirm drift with $p = 1/(i+1)$.
        \item \textbf{Early accept $H_0$ (no drift):} If $c_i / i > 2\alpha$ and $i \geq B_{\min}$, the running exceedance rate far exceeds the nominal level; terminate and declare no drift with $p = (c_i + 1)/(i + 1)$.
    \end{itemize}
    \item \textbf{Terminal decision:} If $B_{\max}$ is reached, compute the standard empirical p-value: $p = (c_{B_{\max}} + 1) / (B_{\max} + 1)$. Drift is confirmed if $p < \alpha$.
\end{enumerate}

\textbf{Type~I Error:} ASPT reports the usual permutation p-value at the point where it stops, $p = (c_i + 1)/(i + 1)$. The combination of the two stopping rules, however, is not an exact level-$\alpha$ test. The early-reject rule alone rejects with probability $1/21 \approx 0.048$ under the null hypothesis, because it stops at $i = 20$ whenever the first 20 permuted AUCs are all below the observed one. If at least one of them is above it, the test can still continue to $B_{\max}$ and reject there. A simulation of the stopping rules with exchangeable statistics under the null hypothesis (400{,}000 repetitions) gave a rejection rate of 0.059 at $\alpha = 0.05$, compared with 0.045 for a fixed test with 199 permutations, and an average of 16.4 permutations per test. A sequential test with exact level, such as the sequential p-value of \citet{BesagClifford1991}, could replace these rules but was not used in the experiments. In addition, to save time, each permuted AUC is computed with 2-fold cross-validation, while the observed AUC uses 5-fold cross-validation (Step~2). The permuted and observed statistics are therefore not computed in the same way, and the p-value is approximate.

\textbf{Computational Savings:} ASPT logs the number of permutations executed per invocation. With $\alpha = 0.05$ and $B_{\min} = 10$, the earliest possible confirmation is at $i = 20$, where $1/21 \approx 0.048 < \alpha$, so a clear drift costs 20 permutations instead of $B_{\max} = 199$. Clear non-drift cases can stop after $B_{\min} = 10$ permutations, and only cases close to the decision boundary use the full budget.

\textbf{Interaction with the AUC Threshold:} ASPT runs only when the AUC exceeds the screening threshold $\tau$. Under the null hypothesis, the AUC of a classifier trained on shuffled labels stays close to 0.5, and with $N_{ref} = 500$ and $N_{cur} = 200$ it rarely moves far from that value. An observed AUC above $\tau = 0.7$ is therefore far into the tail of the permutation distribution, and ASPT is expected to confirm almost every alarm that reaches it. ASPT affects the decision mainly when $\tau$ is set closer to 0.5, which the sensitivity analysis of Experiment~3 examines.

\subsection{Step 4: Feature Ranking via TreeSHAP}
Once ASPT confirms drift ($p < \alpha$), EADD reports which features drive the separation between the two windows. D3 \citep{Gozuacik2019} discards the trained classifier after computing the AUC, although the classifier has learned which features differentiate the reference data from the current data. Following \citet{Maggio2021}, EADD explains the discriminative classifier with SHAP.

EADD applies \textbf{TreeSHAP} \citep{Lundberg2017, LundbergInteraction2020} to a LightGBM classifier trained on $W_{ref} \cup W_{cur}$. TreeSHAP computes exact Shapley values \citep{Shapley1953} in polynomial time for tree-based models. The per-feature ranking is computed as follows:
\begin{enumerate}
    \item Compute SHAP values using TreeSHAP
    \item Calculate the mean absolute SHAP value per feature: $\text{Importance}_i = \frac{1}{n} \sum_{j=1}^{n} |\text{SHAP}_{ij}|$
    \item Normalise to a contribution vector: $s_i = \frac{\text{Importance}_i}{\sum_k \text{Importance}_k}$, so that $\mathbf{s} = (s_1, \ldots, s_d)$ sums to 1
    \item Rank the features by $s_i$
\end{enumerate}

EADD also computes TreeSHAP interaction values \citep{LundbergInteraction2020} on a sample of 100 points and reports their mean absolute values for each feature pair. The ranking and the interaction values are provided as diagnostic output; their accuracy is not evaluated in this thesis.

After a confirmed drift, the reference window is replaced by the current window (Step~1). How the deployed model is then adapted, for example by retraining it on recent data (Section~\ref{sec:mitigation}), is outside the scope of this thesis.

\section{Baseline Drift Detectors}
\label{sec:baselines}
All baselines were run in this thesis on the same streams and with the same seeds as EADD; no published results were copied.

\textbf{D3-LightGBM:} D3 \citep{Gozuacik2019} with its logistic regression replaced by LightGBM with the same hyperparameters as EADD. It uses EADD's window sizes ($N_{ref} = 500$, $N_{cur} = 200$), 2-fold cross-validation and the fixed threshold $\tau = 0.7$. As in the original D3, the oldest 200 samples are discarded after each check, so D3 checks the stream every 200 samples, while EADD checks it every 50 samples. D3-LightGBM is the only version of D3 used, so that the comparison with EADD is not confounded by the classifier or the window sizes.

\textbf{Detectors from the \citet{Lukats2024} benchmark:} six fully unsupervised detectors, each run with 500 observed samples to match EADD's reference window and otherwise with the default settings of the benchmark implementation:
\begin{itemize}
    \item \textbf{BNDM} \citep{BNDM2020}: compares each feature in the two halves of a window of $2 \times 500$ samples with a P\'{o}lya tree test and signals drift when any feature differs (tree depth 3, constant 1.0, threshold 0.5).
    \item \textbf{CSDDM} \citep{CSDDM2021}: reduces the data with PCA, clusters it with K-Means and tests the clusters for change (2 clusters, confidence 0.01, feature proportion 0.1).
    \item \textbf{IBDD} \citep{IBDD2021}: converts windows of the stream into images and compares them (20 permutations, update interval 50, one consecutive deviation).
    \item \textbf{OCDD} \citep{OCDD2021}: fits a one-class SVM to the reference data and signals drift when too many new samples fall outside it (threshold 0.3, RBF kernel, $\nu = 0.5$).
    \item \textbf{SPLL} \citep{SPLL2013}: fits a semi-parametric density model to the reference data and tests the log-likelihood of new data (2 clusters, threshold 0.05).
    \item \textbf{UDetect}: applies Shewhart control charts to the standard deviation of windows of the stream (25 training windows of 500 samples).
\end{itemize}
BNDM tests every feature at every sample, which made the benchmark implementation too slow for the 33 features of the INSECTS streams. For this thesis its test was computed for all features at once; a unit test confirms that the test statistics are identical to those of the original implementation, so its detections are unchanged.

\textbf{EADD variants:} for H3, EADD is also run with a full permutation test that always draws $B_{\max} = 199$ permutations and without a permutation test, accepting every alarm with $\text{AUC} > \tau$. The tables call them EADD (full test) and EADD (no test), and EADD with ASPT is EADD (ASPT). Both variants, and EADD itself, are also run at $\tau \in \{0.3, 0.4, 0.5, 0.6\}$ in addition to the default $\tau = 0.7$, except EADD (full test), whose cost at low thresholds is prohibitive. To check whether EADD's lower detection delay comes from its more frequent checks, EADD is also run with a check every 200 samples, the interval at which D3 checks.

\section{Implementation and Validation}
\label{sec:implementation}
All detectors were run in Python 3.13 with LightGBM 4.6, scikit-learn 1.8 and river 0.23. The baseline detectors and the dataset loaders come from the open-source implementation of the \citet{Lukats2024} benchmark, whose authors only included algorithms that could be implemented faithfully from their original descriptions; their unit tests were kept. EADD (\texttt{detectors/eadd.py}) and D3-LightGBM (\texttt{detectors/d3\_lightgbm.py}) were added to this code base. The permutation test of EADD draws its random numbers from its own generator, so EADD, EADD (full test) and EADD (no test) keep the same reference samples and give the same detections whenever their test decisions agree. Unit tests check that ASPT confirms a clear shift after exactly 20 permutations with $p = 1/21$, that it stops early without a shift, that the full test uses all permutations, that the test variants give the same detections when their decisions agree, that EADD raises no alarm on a stable stream and detects an abrupt shift after its onset, and that D3-LightGBM detects a simple shift once. All experiments use fixed random seeds, and the code, scripts and result files are available in the project repository\footnote{\url{https://github.com/NusratBegum/unsupervised-concept-drift-detection}}.

\section{Evaluation Metrics}
\label{sec:metrics}

\textbf{Annotated streams.} A detection matches an annotated drift point if it occurs within a tolerance window of 500 samples after it, and each drift point is matched at most once. For each run, that is, one stream processed with one seed, the following metrics are computed:
\begin{itemize}
    \item \textbf{Recall:} the proportion of annotated drift points that are matched. Higher is better.
    \item \textbf{Mean time to detection (MTD):} the average delay over all annotated drift points, where a matched drift point contributes the number of samples until its matching detection and a missed drift point contributes 500 samples. Lower is better.
    \item \textbf{False alarms (FA):} the number of detections that match no drift point. Lower is better.
    \item \textbf{Runtime:} the time spent inside the detector. Because the runs were executed in parallel, the runtimes used for H3b were measured in a separate run in which only one detector ran at a time.
\end{itemize}
\citet{Lukats2024} compute the MTD only over the drifts that a detector found. With that definition, a detector that finds one drift quickly and misses the others can have a lower MTD than a detector that finds all of them. Counting a missed drift as the full tolerance window avoids this, and keeps MTD comparable between detectors that find different drifts. For the test variants of EADD, the number of permutation tests, the average number of permutations per test, the percentage of tests that stopped before $B_{\max}$ (early stops), and the percentage of alarms that the test rejected are also recorded.

\textbf{Unannotated streams.} Following \citet{Lukats2024}, a Hoeffding tree classifier is evaluated prequentially, each sample being used first for prediction and then for training, and it is replaced by a new tree at every detection. The metrics are its accuracy, the number of detections, and the lift-per-drift (LPD),
\begin{equation}
\text{LPD} = \frac{\text{Acc}_{\text{reset}} - \text{Acc}_{\text{base}}}{\text{number of detections}},
\label{eq:lpd}
\end{equation}
where $\text{Acc}_{\text{base}}$ is the accuracy of a tree trained only on the first 1,000 samples. A detector earns a positive LPD if resetting the classifier at its detections improves accuracy, and the division penalises detectors that reset too often.

\section{Experimental Design}
\label{sec:design}

The experiments are organised by hypothesis. Experiments~1 and~2 use the same runs: EADD, D3-LightGBM and the six benchmark detectors on the four annotated streams with five seeds (42, 142, 242, 342 and 442).

\textbf{Experiment 1 (H1):} compares the recall and the MTD of the detectors, and tests whether EADD has a higher recall and a lower MTD than D3-LightGBM.

\textbf{Experiment 2 (H2):} compares the false alarms of the detectors, and tests whether EADD raises fewer false alarms than D3-LightGBM.

\textbf{Experiment 3 (H3):} compares EADD with ASPT, with a full permutation test and without a test at the default threshold $\tau = 0.7$ on the annotated streams with five seeds. A sensitivity analysis then repeats EADD and EADD (no test) at $\tau \in \{0.3, 0.4, 0.5, 0.6, 0.7\}$.

\textbf{Experiment 4 (RQ3):} runs EADD, D3-LightGBM and the six benchmark detectors on the nine unannotated streams with three seeds (42, 142 and 242) and reports the classifier accuracy, the number of detections and the lift-per-drift.

\subsection{Statistical Analysis}
\label{sec:stats}
The unit of analysis is a run, so each detector has 20 runs on the annotated streams (four streams and five seeds). H1a, H1b and H2 are tested with a one-sided Mann--Whitney U test on the per-run values of EADD and D3-LightGBM. Because the runs of the two detectors are paired by stream and seed, the one-sided Wilcoxon signed-rank test is reported as well. For H3a, which expects no difference, the number of runs in which EADD and EADD (full test) gave identical results is reported together with two-sided tests, and H3b is tested with the one-sided Wilcoxon signed-rank test on the paired runtimes, because each run with ASPT has a counterpart with the full test on the same stream and seed; the Mann--Whitney test is reported as well. In the sensitivity analysis, the false alarms of EADD at each threshold are compared with those of D3-LightGBM with one-sided tests. In Experiment~4, the accuracies of EADD and D3-LightGBM on the nine streams are compared with a two-sided Wilcoxon signed-rank test. All tests use $\alpha = 0.05$.

The Type~I error of ASPT's stopping rules (Section~\ref{sec:eadd}) was estimated by simulating the rules under the null hypothesis, where the observed AUC and the permuted AUCs are exchangeable, with 400{,}000 repetitions.

\chapter{Discussion} \label{chap:discussion}

This chapter interprets the results of Chapter~\ref{chap:results}, answers the research questions, and relates the findings to the studies reviewed in Chapter~\ref{chap:literature}.

\section{Answers to the Research Questions}

\subsection{RQ1: Detection and False Alarms against D3}

\textit{Does EADD detect annotated drifts in real-world data streams more completely and sooner than D3, and does it raise fewer false alarms?}

No. When D3 used the same LightGBM classifier and the same window sizes as EADD, EADD had a lower recall (0.50 vs.\ 0.65), a higher MTD (302 vs.\ 279 samples) and more false alarms (8.9 vs.\ 5.6 per run) on the four annotated INSECTS streams. The difference in false alarms was significant in favour of D3-LightGBM, and the differences in recall and MTD were not significant in favour of EADD.

Two features of the evaluation explain much of the recall gap. First, EADD often signalled a drift shortly before the annotated point, which the matching rule counts as a false alarm followed by a missed drift. When detections up to 500 samples before an annotated point were also accepted, both detectors reached a recall of 0.95, while EADD still raised more false alarms (8.1 vs.\ 5.3 per run). Second, EADD checks the stream every 50 samples, four times as often as D3. More checks give more chances for an early or false alarm, and each alarm leaves EADD unable to signal for about 500 samples while its windows refill. When EADD checked every 200 samples, its recall and MTD were better than those of D3-LightGBM, although not significantly, while it still raised more false alarms (7.3 vs.\ 5.6 per run). Neither observation was part of the planned comparison, so they do not change the test results, but they show that the comparison is sensitive to the check interval and to the exact position of the annotated drift points.

These results differ from the earlier evaluation of EADD, in which EADD detected the gradual and incremental synthetic drifts that D3 missed and raised fewer false alarms on stable synthetic streams. That evaluation compared EADD with D3 using logistic regression and smaller windows, used synthetic data, and computed the MTD only over the drifts that a detector found. With these differences removed, the advantage of EADD on real data was not confirmed.

\subsection{RQ2: The Adaptive Sequential Permutation Test}

\textit{Does the sequential stopping rule of ASPT make the permutation test faster without degrading detection, and how does the AUC threshold affect EADD?}

Yes for the first part. At the default threshold, ASPT gave exactly the same detections as a full permutation test in every run and stopped every test after 20 of 199 permutations, which reduced the detector's runtime by 25\%. At this threshold the test never changed a decision, because an AUC above 0.7 was always far beyond the AUCs obtained with shuffled labels.

The threshold sensitivity shows when the test matters. At $\tau = 0.5$ and below, most alarms were rejected by ASPT, which reduced the false alarms by 31\% to 81\% compared with EADD without a test, and at $\tau = 0.5$ it also improved recall and MTD. ASPT still stopped early in at least 96\% of its tests. The cost is runtime, which more than doubled at $\tau = 0.3$, and even with ASPT, EADD raised more false alarms than D3-LightGBM at every threshold.

\subsection{RQ3: Streams without Annotated Drifts}

\textit{How do EADD and the other detectors behave on real-world streams without annotated drift points?}

EADD and D3-LightGBM behaved almost identically: their classifier accuracies, numbers of detections and lift-per-drift values were close, and the accuracies did not differ significantly. Resetting a classifier at the detections improved accuracy on four streams and reduced it on two. The detector with the most detections, IBDD, had the highest accuracy but a negative lift-per-drift. These proxy metrics therefore do not separate EADD from D3.

\section{Relation to Previous Studies}

\citet{Lukats2024} found D3 to be one of the strongest unsupervised detectors, with the best mean time ratio on INSECTS Abrupt. The results agree that D3, here with a LightGBM classifier, is a strong baseline: it matched or exceeded EADD on every metric of the annotated streams. \citet{Lukats2024} also reported that the observed sample size strongly influences the detectors and that some configurations signal drift periodically. Both effects appeared here: OCDD signalled drift exactly every 500 samples, and the recall of CSDDM, IBDD and OCDD came with tens to hundreds of false alarms. BNDM, which signalled drift periodically with few observed samples in their study, was not periodic with 500 samples per window, but it found the fewest drift points. SPLL, which \citet{Lukats2024} found less competitive under the mean time ratio, combined a high recall with the fewest false alarms on these four streams, which shows how much the ranking of detectors depends on the metric and on the streams.

The behaviour of ASPT follows from the theory of the classifier two-sample test \citep{LopezPazOquab2017}. Under the null hypothesis, the AUC of a classifier trained on shuffled labels concentrates near 0.5, so an AUC above 0.7 is far in the tail and a permutation test confirms it; sequential stopping then saves most of the permutations. When the threshold is close to 0.5, the test decides, but because a test is run at every check, the false alarm rate over a whole stream is not controlled. Anytime-valid tests such as E-C2ST \citep{EC2ST2024} address this problem.

The accuracy-based evaluation of the unannotated streams reproduced the concern of \citet{Lukats2024} that classifier accuracy rewards frequent resets: IBDD had the highest accuracy with more than 9,000 detections. Lift-per-drift corrects for this, but on these streams it did not distinguish EADD from D3.

\section{Practical Implementation Considerations}

\subsection{Check Interval, Threshold and Resets}

The experiments show three practical points for discriminative detectors. First, every detection resets the windows, after which the detector cannot signal for about the length of its windows. A false alarm shortly before a real drift can therefore cause the real drift to be missed, so a detector that checks often should also be selective. Second, a threshold of 0.7 made the permutation test unnecessary in these experiments; a lower threshold needs a test to keep the false alarms down and costs more computation. Third, the window sizes and the check interval affected the results more than the significance test did, so they should be chosen for the stream at hand.

\subsection{Proposed MLOps Deployment Architecture}

To move EADD from an offline experiment to a production service, it would be integrated into an MLOps architecture as a separate monitoring service:

\begin{itemize}
    \item \textbf{Data Ingestion Layer (e.g., Apache Kafka):} streams the incoming feature data ($W_{cur}$) to the monitoring service.
    \item \textbf{EADD Monitoring Service:} a container that runs the LightGBM discriminator, the permutation test and the SHAP explainer, and keeps the reservoir sample ($W_{ref}$) in an in-memory store (e.g., Redis).
    \item \textbf{Orchestration and Model Registry (e.g., Apache Airflow, MLflow):} receives a drift report with the AUC, the p-value, $H_{\text{pred}}$ and the feature ranking, and either triggers retraining of the deployed model or alerts the engineers responsible for the top-ranked features.
\end{itemize}

This architecture keeps the cost of the discriminator and the permutation test away from the inference path of the deployed model.

\section{Limitations and Threats to Validity}
\label{sec:limitations}

\textbf{Few Annotated Drifts:} The four annotated streams contain ten drift points, and only major transitions are annotated. Recall and false alarms therefore rest on few events, and some false alarms on the incremental streams may be real changes.

\textbf{Matching Rule:} A detection counts only if it occurs within 500 samples after an annotated point. EADD's recall depended strongly on this choice, because many of its detections came shortly before the annotated points.

\textbf{Dependent Runs:} The five seeds of a stream share the same data, so the 20 runs of a detector are not independent samples. The tests treat them as independent, which overstates the evidence for any difference.

\textbf{Check Interval:} D3 checks every 200 samples and EADD every 50, which is part of their designs but is a remaining difference between them. EADD checking every 200 samples was reported as an additional run.

\textbf{Default Configurations:} All detectors used one configuration with 500 observed samples, while \citet{Lukats2024} tested many configurations per detector. Other configurations may change the ranking.

\textbf{Approximate Permutation Test:} ASPT's stopping rules raise its Type~I error from 0.045 to 0.059 at $\alpha = 0.05$ in simulation, and the permuted AUCs use 2-fold cross-validation while the observed AUC uses 5-fold cross-validation. EADD also tests at every check without correcting for the number of tests, and the permutation test assumes exchangeable samples, which autocorrelated streams violate.

\textbf{Covariate Drift Only:} EADD detects changes in $P(X)$ and cannot detect concept drift that leaves $P(X)$ unchanged \citep{HDPD2024}.

\textbf{Unevaluated Components:} The prediction entropy $H_{\text{pred}}$ and the TreeSHAP feature ranking are reported by EADD but were not evaluated. SHAP explanations are also correlational rather than causal \citep{CausalDrift2025}.

\textbf{Difference from the Conference Paper:} The conference version of this work used synthetic streams, D3 with logistic regression and smaller windows, a single real-world run, and the Drift Severity Index. Its conclusions about EADD's advantage over D3 are not confirmed by the evaluation in this thesis.

\textbf{Adversarial Vulnerability:} \citet{AdvAttackDrift2024} showed that discriminative drift detectors can be evaded by adversarial data streams, and EADD shares this weakness.

\section{Chapter Summary}

With the classifier and the window sizes matched, EADD did not outperform D3-LightGBM on the annotated real-world streams: its recall was lower, its detection delay longer and its false alarms more frequent, so H1 and H2 are not supported. Much of the recall gap came from EADD signalling shortly before the annotated drift points and from its more frequent checks. ASPT gave the same detections as a full permutation test in less time, which supports H3, and at low thresholds it rejected most alarms and reduced the false alarms substantially. On the unannotated streams, EADD and D3-LightGBM were indistinguishable.

\chapter{Conclusion and Recommendations} \label{chap:conclusion}

\section{Summary of Findings}

This thesis investigated adversarial validation, the classifier two-sample test, as a technique for unsupervised feature drift detection. It proposed EADD, which extends the discriminative approach of D3 \citep{Gozuacik2019} with a long-memory reference window, a permutation test with sequential stopping, prediction entropy monitoring and a feature ranking. The contributions are the following:

\begin{enumerate}
    \item An integrated framework that combines a classifier two-sample test \citep{LopezPazOquab2017}, a reservoir-sampled reference window \citep{Vitter1985}, prediction entropy monitoring and an adaptive sequential permutation test, and that ranks the features behind each confirmed drift.
    \item An adaptive sequential permutation test (ASPT) that adds a sequential stopping rule, motivated by \citet{Gandy2009}, to the classifier two-sample test. On four annotated real-world streams, ASPT gave the same detections as a full permutation test in all 20 runs with 25\% less runtime, and at low AUC thresholds it reduced false alarms by up to 81\% compared with no test. A simulation shows that the rule raises the Type~I error of a single test from 0.045 to 0.059 at $\alpha = 0.05$.
    \item A comparison of EADD with D3 and six other unsupervised detectors on thirteen real-world streams, with D3 using the same classifier and window sizes as EADD and the differences tested for significance.
\end{enumerate}

On four annotated INSECTS streams, EADD had a lower recall (0.50 vs.\ 0.65) and a higher MTD (302 vs.\ 279 samples) than D3-LightGBM, so H1 is not supported. EADD also raised more false alarms (8.9 vs.\ 5.6 per run), and this difference was significant in favour of D3-LightGBM, so H2 is not supported.

ASPT gave the same detections as a full permutation test in all 20 runs with 25\% less runtime, so H3 is supported. At thresholds of 0.5 and below, it reduced the false alarms of EADD by 31\% to 81\%.

On the nine unannotated streams, EADD and D3-LightGBM gave almost the same classifier accuracy (65.4\% vs.\ 65.7\%) and lift-per-drift.

\section{Limitations}

The main limitations, discussed in Section~\ref{sec:limitations}, are the small number of annotated drift points, the dependence of the results on the matching rule and the check interval, the use of one configuration per detector, and the dependence between runs on the same stream. ASPT is not an exact level-$\alpha$ test, the error rate over a whole stream is not controlled, and the prediction entropy and the feature ranking were not evaluated.

\section{Recommendations for Application}

The results lead to the following recommendations for practitioners who deploy discriminative drift detectors:

\textbf{Start from D3 with a Strong Classifier:} On the annotated real-world streams, D3 with a LightGBM classifier was at least as good as EADD on every metric and much faster. It is a strong default for unsupervised feature drift detection.

\textbf{Match the Check Interval to the Windows:} Every detection resets the windows. Checking very often gives more chances for early or false alarms, each of which leaves the detector unable to signal for about the length of its windows.

\textbf{Use a Permutation Test Only with a Low Threshold:} At an AUC threshold of 0.7, the permutation test never changed a decision. With a lower threshold, a test is needed to keep the false alarms down, and sequential stopping keeps most tests to 10 to 20 permutations.

\textbf{Evaluate on Annotated Real Data and Count Missed Drifts:} Synthetic streams and an MTD computed only over the drifts that a detector finds can favour one detector over another. Evaluations should use annotated real-world streams where possible and report recall, MTD with missed drifts counted, and false alarms together.

\textbf{Treat the Feature Ranking as a Lead:} The TreeSHAP ranking points to the features that separate the two windows. Because its accuracy has not been evaluated and SHAP is correlational \citep{CausalDrift2025}, it should be treated as a lead for investigation rather than as a diagnosis. In regulated sectors, where unexplained model updates may conflict with transparency requirements \citep{GoodmanFlaxman2017}, it can also document which features changed before each update.

\section{Suggestions for Future Research}

Based on the findings, future research could pursue the following directions:

\begin{enumerate}
    \item \textbf{Selective Resets:} Keeping the reference window after an alarm that is not confirmed by later checks, so that an early or false alarm does not make the detector blind to a real drift that follows.
    \item \textbf{Anytime-Valid Testing:} Replacing the per-check permutation p-value with e-values \citep{EC2ST2024} to control the false alarm rate over a whole stream, and using a sequential test with exact level \citep{BesagClifford1991}.
    \item \textbf{More Annotated Streams and Configurations:} Evaluating the detectors on more real-world streams with annotated drift points, with several configurations per detector as in \citet{Lukats2024}, and with matching rules that accept detections close to an annotated point.
    \item \textbf{Evaluating the Feature Ranking and $H_{\text{pred}}$:} Measuring how accurately the TreeSHAP ranking identifies drifting features, and whether $H_{\text{pred}}$ gives earlier warnings than the AUC.
    \item \textbf{Covariate and Concept Drift Decomposition:} Integrating the decomposition of \citet{HDPD2024} to separate $P(X)$ shifts from $P(y|X)$ shifts when delayed labels become available.
    \item \textbf{Adversarial Robustness:} Developing defences against adversarial drift evasion attacks \citep{AdvAttackDrift2024}.
\end{enumerate}

\section{Concluding Remarks}

This thesis studied adversarial validation as a technique for feature drift detection and proposed EADD, an integrated framework that combines established methods: the classifier two-sample test \citep{LopezPazOquab2017}, reservoir sampling \citep{Vitter1985}, sequential stopping of Monte Carlo tests \citep{Gandy2009} and TreeSHAP \citep{Lundberg2017, LundbergInteraction2020}. When D3 was given the same classifier and window sizes, EADD did not outperform it on annotated real-world streams, and the earlier advantage of EADD did not hold under this fairer comparison. The sequential permutation test did what it was designed to do: it made the permutation test faster without changing its decisions, and it reduced false alarms when the threshold was low. The main lesson is that the windows, the check interval and the evaluation protocol of a discriminative drift detector matter more than its significance test, and that claims about such detectors should be tested on annotated real-world data with the confounding choices held equal.
